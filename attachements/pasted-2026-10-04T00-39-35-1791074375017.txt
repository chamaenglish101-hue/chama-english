PROBLEMA 2 — PREMIUM ESTÁ SENDO LIBERADO SEM PAGAMENTO:
Atualmente existe uma falha de segurança: aparentemente o usuário consegue clicar em uma opção de simulação e receber Premium sem realmente pagar.

CORRIJA ISSO COMPLETAMENTE.

REGRA OBRIGATÓRIA:
O Premium NUNCA deve ser liberado pelo frontend simplesmente porque o usuário clicou em "pagar", "simular", "sucesso" ou qualquer botão semelhante.

O servidor deve verificar o status REAL do pagamento na Stripe antes de conceder Premium.

Use uma arquitetura segura:
1. Usuário inicia o pagamento.
2. Stripe cria o pagamento/PaymentIntent ou Checkout Session apropriado.
3. Para PIX, mostrar os dados/QR Code gerados pela Stripe.
4. O usuário realiza o pagamento.
5. A Stripe confirma o pagamento.
6. O backend recebe/verifica a confirmação da Stripe através do mecanismo oficial de confirmação/webhook.
7. Somente depois de confirmar que o pagamento está realmente pago, o backend libera o Premium para aquele usuário.
8. O frontend nunca pode conceder Premium sozinho.
9. Um pagamento cancelado, expirado, pendente ou falho NÃO pode liberar Premium.
10. Não confiar em parâmetros enviados pelo navegador para determinar que o pagamento foi concluído.

SEGURANÇA:
- Verifique a assinatura dos webhooks da Stripe.
- Não coloque a Stripe Secret Key no frontend.
- Não exponha chaves secretas no código ou nas variáveis públicas.
- Vincule cada pagamento ao usuário correto do Chama English.
- Evite que o mesmo pagamento possa conceder Premium várias vezes.
- Garanta que atualizar/recarregar a página não conceda Premium sem confirmação real.
- Garanta que alguém não consiga alterar uma resposta do frontend para se passar por pagamento aprovado.

MODO DE TESTE:
Se o projeto precisar manter Stripe Test Mode para desenvolvimento, mantenha-o separado do fluxo de produção. O usuário final NÃO deve conseguir usar funções de teste para obter Premium.
